## 1. 结论

| 项 | 结果 |
|---|---|
| Overhaul SFR | **5,000 / 5,000 通过**（D1-B 修复后的数据集，0 个 `error` 记录） |
| Underhaul SFR | **5,000 / 5,000 通过** |
| 崩溃用例（§3.1.4） | D1-B 之后不再存在；未修基线（`sfr-cases.pre-d1.jsonl.gz`）的 277 条也会算出有限值 |
| 独立手算验证（§4.6 R1.5h，不可省） | ✅ `packages/kernel/test/hand-calc.test.ts` |
| 分歧区单独报告（§4.6 R1.5i） | 见 §5（R0 定位的 `checker`/`fuel_mod`/`mixed` 区域全部覆盖） |
| 确定性（R1.0a） | 冻结引擎逐位可复现 → 容差 1e-5 是保险而非必需 |

> **注意**：本报告里的「通过」= 15 个数值字段（整数精确相等、浮点相对 1e-5 内，
> 实测逐位相同）。`lite` 引擎（应当消失的第二实现）从不作为对拍目标。

## 2. 移植了什么（文件级映射）

| Java | TS | 说明 |
|---|---|---|
| `multiblock/Multiblock`（`recalculate`/`clearData`/`getBlocks`） | `kernel/src/sfr/reactor.ts` 的 `recalculate/clearData` | 扫描顺序与状态重置是语义 |
| `BlockGrid` + `BoundingBox.forEachPosition` | `kernel/src/geometry.ts` `CuboidGrid` | 外部尺寸 `(x+2,y+2,z+2)`，x→y→z 遍历 |
| `Direction/Axis/Edge/Vertex` | `kernel/src/geometry.ts` | 顺序即语义 |
| `overhaul/fissionsfr/Block` | `kernel/src/sfr/reactor.ts` `SfrBlock` | 含 `setToggled`（中子屏蔽开/闭） |
| `OverhaulSFR`（1878 行，取物理部分） | `kernel/src/sfr/reactor.ts` | 三阶段：base → shutdown → partial shutdown |
| `OverhaulSFR.Cluster` + `getClusterBlocks` + `wallCheck` | 同上 `Cluster` / `clusterBlocks` / `wallCheck` | 分层 BFS，层序展平 |
| `NCPFPlacementRule.isValid` | `kernel/src/rules.ts` | 被 SFR/USFR(及后续 MSR/Turbine) 共用 |
| `NCPFElementDefinition.matches`（用于规则目标） | `rules.ts` `targetMatches` + `definition.identity` | **不**复刻 `matches()` 的自反性 bug |
| `UnderhaulSFR`（661 行） | `kernel/src/usfr/reactor.ts` | 单燃料、`calculateCore`/`calculateCooler`/stats |
| `planner/ncpf/configuration/overhaulSFR/BlockElement` 等 | `kernel/src/sfr/config.ts` | 模板视图（flags/stats/recipes/toggled） |
| `module/overhaulSFR/*` 的数值字段声明 | `ncpf/src/moduleSchema.ts` | 声明式 schema 取代 120 个手写类 |
| `NCPFLegacyRecipeElement.getName()` / `getOutputRatio()` | `kernel/src/sfr/config.ts` / `ncpf/src/module.ts` | 含 `*amount`，否则配方无法匹配 |

不移植（明确属于 UI 或后续阶段）：`Decal`（贴图装饰）、`renderOverlay`、`getTooltip`、
`Suggestor`（R4）、`toDesign`/`convertToMSR`（R2/R1.6b）。

## 3. 铁律的落地

| 铁律（§11.2） | 落地方式 |
|---|---|
| 物理只有一份实现 | 内核只有 `OverhaulSfrReactor`/`UnderhaulSfrReactor`，没有第二份 `lite`；R4 的快速入口将复用同一份代码 |
| 逻辑只用英文 canonical / 元素身份 | 数据集的键是 `definition.toString()`；`displayName` 只用于显示 |
| 引用配方不用「索引 + 结构相等」 | 配方按 `definition.toString()` 全文匹配，查不到**抛错**（早期版本静默忽略，导致 170 个辐照器少算） |
| 缺 key 整条回退 | i18n 层，见 `docs/r1/r1.2-i18n.md` |
| 写分两种语义 | R1.4，见 `docs/r1/r1.4-ncpf-io.md` |
| 数据名身份键四段式 | `docs/r1/r1.2-*` + `packages/ncpf/test/identity.test.ts`（29 冲突 → 0） |
| 新增语言零代码 | i18n 语言包 |

## 4. 移植过程中发现的真实缺陷（都被黄金数据集抓到）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 600 例中 3 例失败（`mixed`） | 数据集用 `getName()` 记录模板，散热器/反射器变体不可区分 | 数据集 v3 改单射命名 + 内核记录 `ambiguous` 作为哨兵 |
| 2 | 5,000 例中 3 例 `rawOutput` 差 1 | `float` 字段读成 double（fuel `efficiency` 1.05 → 1 ULP） | 按 `moduleSchema` 的字段类型收窄；`fadd/fmul/fdiv` 逐步 `fround` |
| 3 | 170 个辐照器方块收不到配方（静默） | 配方名漏了 `*amount` | `stackToString` 复刻 Java；匹配失败改为抛错 |
| 4 | `shutdownFactor` 恒为 1，`offOutput` 恒为 0 | 我在 `clearData` 里多重置了 `offOutput`（Java 故意不重置） | 对齐 Java 的字段重置清单 |
| 5 | 277 例冻结引擎 NPE | `OverhaulSFR.java:1024` 缺 null guard | D1-B 修复并重生成（见 `docs/r1/d1-decision.md`） |
| 6 | 石墨慢化剂用例的 `moderatorLines` 为 0 | 重传播循环跳过 `!wasActive` 的单元，清空连线计数但恢复通量 | 不是 bug，是旧实现的语义；已写入手算测试的注释 |

调试工具（保留在仓库，供 R1.6b/c 复用）：
`GoldenGen --dump-blocks-id <id>`、`GoldenGen --repeat N`、
`NCPL_DUMP_ID=... vitest run packages/kernel/test/block-dump.test.ts`、
`node tools/ts/diff-block-dumps.mjs <java> <ts>`（按 float32 归一化比较，簇按位置划分比较）。

## 5. 分歧区（R0 定位）与 R1 的对拍覆盖

R0 的结论是「分歧集中在慢化剂连线 + 簇构建」，并按策略给出分歧率。
R1 的 5,000 例是同一批布局，因此覆盖情况可直接对照：

| 策略 | SFR 例数 | USFR 例数 | R1 结果 |
|---|---:|---:|---|
| `random` | 725 | 688 | 全通过 |
| `mixed` | 732 | 727 | 全通过（含原先 277 个崩溃用例的同类布局） |
| `fuel_mod` | 709 | 712 | 全通过 |
| `fuel_only` | 663 | 725 | 全通过 |
| `casing_only` | 738 | 755 | 全通过 |
| `fuel_heatsink` | 675 | 717 | 全通过 |
| `checker` | 758 | 676 | 全通过 |

> `casing_only` 在 R0 是「100% 平凡分歧」（零除/未初始化）。TS 侧按 §3.1.5 定义域规范化后
> 与旧实现的 `NaN`/越界行为对拍一致（比较层两侧同时规范化，见 `stats.ts`）。

## 6. 性能基线（供 R4 参考）

Node 24、单线程、Vitest 内：SFR 5,000 例 ≈ 4.4 s（≈1,100 例/s，含重建），
USFR 5,000 例 ≈ 1.9 s。R4 的阈值（7×7×7 生成 < 2 s）需要单独测，但内核本身不是瓶颈。
