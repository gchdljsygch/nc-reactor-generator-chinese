# R1.2 — i18n 基础设施（`@ncplanner/i18n`）

> 对应 `docs/rewrite-plan-r1-r5.md` §4.3 R1.2a–R1.2f；验收标准见同文档 §3.3。
> 代码：`packages/i18n/src/**`，测试：`packages/i18n/test/**`，语言包：`lang/*.json`，
> 迁移工具：`tools/ts/migrate-legacy-translations.mjs`，迁移报告：`docs/r1/r1.2-translation-migration.md`。

## 1. 这个包解决什么

旧实现把翻译放在**渲染末端**，用「英文原文当 key + 子串替换」（`SimplifiedChineseLocalizer`，
见 `docs/refactoring-plan.md` 根因 1/2）。本包把它换成：**稳定 key + 整条回退 + 数据名独立身份键**。

| 铁律（`docs/rewrite-plan-r1-r5.md` §11.2） | 本包如何保证 |
|---|---|
| 缺 key **整条**回退，绝不半翻译 | 回退链按**条目**逐级查找，命中即整条返回；查不到返回 key 本身（`MessageBundle`） |
| i18n key 是稳定 ID，禁止拼接 | `tr(key, args)` 的模板在语言包里带 `{0}`/`{name}` 占位符，调用点不做字符串拼接 |
| 数据名身份键四段式 | `DataNameBundle` 只用 `<config>/<cfgType>/<type>\|<definition>` 查表 |
| 新增语言零代码 | 语言包是纯 JSON，`loadPack()` / `registerPack()` 运行时可加载 |
| 逻辑只用英文 canonical | `DataNameBundle.name()` 只用于显示；查不到时回退 `NCPFElement.canonicalName` |

## 2. 文件结构

```
packages/i18n/src/
├── locale.ts              # locale 解析与回退链（zh_CN → zh → en_US）
├── format.ts              # ICU 子集：{0}/{name} 占位符 + 复数形态选择
├── pack.ts                # 语言包格式、loadPack/parsePack/mergePacks、LocaleSource 接口
├── messageBundle.ts       # tr / plural / trOr
├── dataNameBundle.ts      # 四段式身份键 → 数据名
├── missingKeyReporter.ts  # 开发告警 + 聚合（CI 门禁数据源）
├── localeManager.ts       # 当前 locale / 监听器 / 持久化 hook / 语言包注册表
└── index.ts
```

依赖方向：`@ncplanner/i18n` → `@ncplanner/ncpf`（复用 `elementIdentityKey` / `identityKey`）。
本包没有 IO、没有 UI、不读 `settings.dat`。

## 3. 回退链与「整条回退」

```
zh_CN  →  zh  →  en_US  →  key 本身
```

- `LocaleManager.chain()` 给出当前链；`localeChain('zh_CN') === ['zh_CN','zh','en_US']`。
- 每一级都是一个**独立的语言包**；某个 key 在某级缺失就前往下一级，**不会**把两级拼起来。
- 链的最后一跳是 key 本身（稳定 ID），因此界面上永远不会出现「看起来像英文但其实是半句话」的文本。
- 数据名的最后一跳是元素的英文 canonical 名（`NCPFElement.canonicalName`），同样是整条。

## 4. 语言包格式

```jsonc
{
  "meta": {
    "locale": "zh_CN",        // 必填，language[_REGION]
    "name": "简体中文",
    "version": "1.0.0",
    "base": "en_US",
    "status": "draft" | "seed" | "complete"
  },
  "messages": {
    "menu.add": "添加 {0}",
    "stat.cells": { "one": "{0} 个燃料单元", "other": "{0} 个燃料单元" }
  },
  "elements": {
    "NuclearCraft/Overhaul SFR Configuration/legacy_block|nuclearcraft:solid_fission_cell": "燃料单元"
  },
  "sources": { "menu.add": "Add {0}" },                       // 审计用：key → 英文原文
  "needsReview": [ { "source": "Power", "translation": "功率", "reason": "fragment-word" } ]
}
```

约定：

- UTF-8、无 BOM；`en_US` 是规范源。`sources` / `needsReview` 是审计元数据，运行时不解释、只保留。
- 一个语言可以拆成多个文件（`zh_CN.messages.json` + `zh_CN.elements.json`）：`registerPack()` 默认按
  **条目**合并，`mergePacks()` 保证同一条消息永远整条来自某一个包。
- 未注册的语言包不影响其它语言；`loadPack()` 只在 `meta.locale` 缺失或格式非法时抛 `PackFormatError`。
- **新增一门语言 = 放一个 JSON 文件**（内置放 `lang/`，第三方运行时 `manager.loadPack(json)`），无编译、无代码改动。

## 5. 占位符与复数（ICU 子集）

自己实现，不引入 `intl-messageformat` 等依赖（无新 npm 依赖）。

**占位符**：`{0}`、`{1}`（位置参数）与 `{name}`（命名参数）。
未提供值的占位符**原样保留**（`添加 {0}`）——不猜、不清空，便于审计工具 grep。

**复数（已选定的机制）**：一个 key 的值为**复数形态对象**，如

```jsonc
"stat.cells": { "one": "{0} fuel cell", "other": "{0} fuel cells" }
```

选择该机制而不是 `key.one` / `key.other` 两个独立 key，理由：**两个 key 无法整条回退**——
可能出现 `key.one` 命中中文包而 `key.other` 命中英文包，正好制造半翻译。

规则：

| 语言 | `plural(key, n)` 行为 |
|---|---|
| `zh` / `ja` / `ko` / `th` / `vi` / `id` …（CLDR 单形语言，见 `format.ts` 的 `SINGLE_FORM_LANGUAGES`） | 永远使用**唯一形态**（值为字符串则直接用；值为对象则取 `other`，否则取 `one`）→ 中文无复数变化 |
| `en` 及其它语言 | `n === 1 → one`，否则 `other` |

- 参数约定：在 `plural()` 中，**数量固定占 `{0}`**，同时可写作 `{n}` / `{count}`；额外的位置参数从 `{1}` 开始。
- 若某一级缺少所需形态（例如 `en_GB` 只定义了 `one`，而 `n = 5`），该级视为**无法提供**，整条回退到下一级
  （`packages/i18n/test/plural.test.ts` 有断言）。
- **范围限制**：只实现「单形」与 `one`/`other` 两类规则。`few` / `many` / `zero` 可以出现在语言包里并被保留，
  但目前不会按规则自动选中（需要完整 CLDR 规则表与相应语言需求）。这一限制是显式的，不假装支持。

**语序**：模板整体存在于语言包中，参数位置由译文决定，例如

```jsonc
// en_US
"tooltip.recipe": "{input} to {output}"
// zh_CN
"tooltip.recipe": "由 {input} 生成 {output}"
```

## 6. `DataNameBundle` — 数据名身份键

键为四段式（R0 发现 #4）：

```
<config>/<cfgType>/<type>|<definition>
例：NuclearCraft/Overhaul SFR Configuration/legacy_block|nuclearcraft:solid_fission_cell
```

- `config` = `Configuration.getName()`（即 `plannerator:configuration_metadata.name`，如 `NuclearCraft`）；
  `cfgType` = 配置类型名（如 `Overhaul SFR Configuration`）；后两段来自 `definition.type` / `definition.toString()`。
- 复用 `@ncplanner/ncpf` 的 `elementIdentityKey()` / `identityKey()`，本包不自己拼格式、不重新解析配置。
- 仅 `type|definition`（660 个键）时**有 29 个键对应互相冲突的显示名**；加命名空间后冲突为 0，
  全量 948 元素的证据在 `packages/i18n/test/dataNames.test.ts` 与
  `docs/r0/translation-migration.md` §4。
- ⚠️ 参数命名差异（记录，未改其它包）：`packages/ncpf/src/identity.ts` 的
  `elementIdentityKey(container, configId, element)` 文档把前两段描述为「文件名 + 配置 id」
  （`nuclearcraft.ncpf.json` / `nuclearcraft:overhaul_sfr`）。而 `ElementDump`、`datasets/ncpf-elements.jsonl`
  与 `lang/*.elements.json` 用的是「配置名 + 配置类型名」。拼接结果形状一致，但两处文档口径不同，
  后续 R1.3 若提供 `Configuration` → 身份键的适配函数，需要把这一处对齐。

## 7. `MissingKeyReporter` — 告警与聚合

```ts
const reporter = new MissingKeyReporter();               // 开发模式：console.warn，按 kind:key 去重
const messages = new MessageBundle(locales, { reporter });
messages.tr('menu.add', ['Fuel Cell']);
reporter.summary();   // { total, unique, byKind, byFallback, byLocale, keys }
reporter.format();    // 单行汇总，可打进 CI 日志
```

`fallback` 枚举说明「这句话是怎么来的」：

| fallback | 含义 |
|---|---|
| `self` | 当前 locale 命中（**不记录**） |
| `language` | 命中裸语言级（`zh_CN` 用了 `zh`） |
| `canonical` | 命中规范语言级（`en_US`） |
| `key` | 都没有 → 返回 key 本身 |
| `canonical-name` | 数据名都没有 → 返回元素英文 canonical 名 |

CI 门禁用法：`byFallback.canonical + byFallback.key` 即「未翻译 key 数」，
`byFallback['canonical-name']` 即「未本地化元素数」。当前基线：
元素 948 个中 26 个已翻译（922 个回退英文），UI 文案 1,101 条中 283 条已自动重新 key 化
（见迁移报告）。

## 8. 持久化 hook

```ts
export interface LocalePersistence {
  read(): string | null | undefined;
  write(locale: string): void;
}
```

`LocaleManager` 在构造时 `read()`（显式传入的 `initialLocale` 优先），在 `setLocale()` 时 `write()`。
本包**不接触** `settings.dat`：R2.11 的 `config2` 迁移负责把它接到真实设置文件上。

## 10. 已知局限 / 不在本包范围

1. **没有从代码抽取英文串**（R3.8）：`lang/en_US.messages.json` 目前是「种子」包，只含遗留表里恰好存在的
   283 条消息；完整规范源要在 R3.8 抽取代码字符串时生成，同时补齐复数形态与占位符。
2. **旧表无法还原参数位置**：迁移工具不猜 `{0}` 的位置，带冒号/空白的 818 条进入 `needsReview` 人工队列。
3. **复数规则不完整**：`few` / `many` 未按规则选择（见 §5）。
4. **无语言包热重载/文件监听**：按任务要求只提供 `loadPack(json)`。
5. **无「禁止裸字符串」lint 规则**（R1.1d）与覆盖率 CI 门禁脚本（R1.1c/§11.3）：本包只提供聚合数据，
   门禁脚本属仓库工程约定那条工作流。
6. **字体/排版**（R3.9）与本包无关：本包只产出文本。
